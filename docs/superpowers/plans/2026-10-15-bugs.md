## Review Focus

These are inputs the spec implies but doesn't list. Each one has a test in the task that owns it.

1. **Focus time added between the note write and the mark** (bug 2): the second `markLogged` marks only what was written, so time added in between stays unlogged. Test: `markLogged up to what was written leaves later focus unlogged` (Task 2).
2. **A task with 0 minutes** (bug 5): it gets skipped, not placed as a zero-length block, and it doesn't stall the queue. Test: `test_a_zero_minute_task_is_skipped` (Task 5).
3. **A meeting that ends exactly at 00:00 of the plan date** (bug 5): it doesn't block the day. Test: `test_other_days_are_ignored` (Task 5).
4. **A task pinned to a weekday that has already passed this week** (bug 6): it overflows instead of landing on a past day. Test: `test_a_task_pinned_to_a_past_day_overflows` (Task 6; this is a guard, so it passes before the fix too).
5. **A symlink whose target doesn't exist yet** (bug 8): the write creates the target and the link stays a link. Test: `test_write_through_a_dangling_symlink_creates_the_target` (Task 8).

Accepted trade-off (spec's choice, not a defect): with write-then-mark, two sessions that end at the same moment can both write the same focus line, which is the same as `flushDay`. Before this change the time could be lost. Now it can be written twice.

## Decisions made in this plan (check them in review)

- **Bug 1:** only the leading `\s*` (between `name:` and the value) becomes `[ \t]*`. The trailing `\s*$` stays, because in Python it's what absorbs a `\r` from a CRLF file (the capture excludes only `\n`). It can't cross lines: the capture is lazy, so `$` matches at the first line end.
- **Bug 4:** "refuse to clear unparsed lines" means `apply` still runs, but lines that aren't `- ` bullets (plain text, `* x`, `1. x`) stay in the fresh `inbox.md` below the placeholder, and `apply` reports how many. They aren't archived until they become bullets, so they're never archived twice. "Archive the raw inbox text" means bullet lines go to the archive verbatim (indentation kept). The header and instructions that `apply` and the seed `inbox.md` write are never archived or kept. `parse` also reports the unparsed lines so the skill can mention them before classifying.
- **Bug 6:** the today-onward rule applies only to the default (no `--week-start`). An explicit `--week-start` plans every day of that week, as it does today. The plan-week skill stops passing `--week-start` interactively (so users get the fix). The scheduled prompt keeps `--week-start <monday>` because it deliberately plans the coming week.
- **Bug 7:** the merged pool is: triage output for today (if triage ran this morning), `tasks-<yesterday>.json`, and `week-tasks-<today>.json` (from plan-week, the file bug 6 renames). Without the last one, the rename would cut plan-week's per-day files out of the morning flow.
- **Versions:** patch bumps: `planner` 0.4.0 → 0.4.1, `tasks` 0.3.0 → 0.3.1, `task-track` 0.3.0 → 0.3.1. `setup/pyproject.toml` isn't bumped: the spec doesn't ask for it, and it would change `setup/uv.lock`.

- [ ] **Step 4: Write first, then mark**

`plugins/task-track/hooks/register.tsx`, replace `flushFocus`:

```ts
/**
 * Writes today's not-yet-logged focus on `slug` to its task Log and the daily note, then marks it logged.
 * Notes first, as flushDay does: a failed write leaves the time unlogged for the next try instead of losing it.
 */
async function flushFocus($: EngineInterface, slug: string, path: string): Promise<void> {
  const before = await changePomo($, file => file)
  if (!before) return
  const pending = unlogged(before, slug)
  if (pending.ms < MIN_LOGGED_MS) return
  const { date, time } = stamp(new Date(await $.clock.now()))
  await writeFocus($, slug, path, date, time, focusText(pending))
  const written = { ms: before.dayMs[slug] ?? 0, blocks: before.dayBlocks[slug] ?? 0 }
  // Only what was written: focus added meanwhile stays unlogged, and a day that rolled over meanwhile is not marked.
  await changePomo($, file => (file.day === before.day ? markLogged(file, slug, written) : file))
}
```

`changePomo($, file => file)` still rolls the day and flushes a finished day, as the old call did. When nothing changes it only refreshes the cached state (`next === current`).

def load_busy(path, date_iso):
    """Fixed busy blocks [title, start_min, end_min] for the date, clipped to it:
    a meeting that crosses midnight blocks its part of this day."""
    if not path or not os.path.exists(path):
        return []
    with open(path) as f:
        data = json.load(f)
    blobs = data if isinstance(data, list) else [data]
    day0 = dt.datetime.fromisoformat(date_iso)
    day1 = day0 + dt.timedelta(days=1)
    out = []
    for blob in blobs:
        for ev in (blob.get("events", []) if isinstance(blob, dict) else []):
            start, end = ev.get("start", {}), ev.get("end", {})
            if "dateTime" not in start:
                continue  # skip all-day; they don't block time-of-day
            s = _wall(start["dateTime"])
            e = _wall(end["dateTime"]) if "dateTime" in end else s + dt.timedelta(minutes=30)
            s, e = max(s, day0), min(e, day1)
            if e <= s:
                continue  # another day
            out.append([ev.get("summary", "(busy)"), (s - day0) // dt.timedelta(minutes=1),
                        (e - day0) // dt.timedelta(minutes=1)])
    return out


def _wall(iso):
    # the wall-clock date and time as written on the calendar (offset ignored)
    return dt.datetime.fromisoformat(iso[:16])

def plan_days(today, week_start, include_weekend):
    """(Monday, ISO dates to plan). No week_start: this week from today on, or
    next week on a Saturday or Sunday. An explicit week_start plans all of it."""
    n_days = 7 if include_weekend else 5
    if week_start is None:

        if today.weekday() >= 5:
            week_start += dt.timedelta(days=7)
        first = max(today, week_start)

    days = [week_start + dt.timedelta(days=i) for i in range(n_days)]
    return week_start, [d.isoformat() for d in days if d >= first]

```python
def write_json(path: Path, data: dict, backups: Path, *, home: Path) -> Path | None:
    saved = backup(path, backups, home=home)
    # A symlinked settings.json (dotfiles) stays a link: write the file it points at.
    target = path.resolve()
    target.parent.mkdir(parents=True, exist_ok=True)
    tmp = target.with_name(target.name + ".tmp")
    tmp.write_text(json.dumps(data, indent=2) + "\n")
    if target.exists():
        shutil.copymode(target, tmp)  # a private (0600) file stays private
    json.loads(tmp.read_text())  # never leave a broken settings file
    tmp.replace(target)
    return saved
```
