---
name: task-switch
description: Park the current task and make another existing task note active. Use on /tasks:task-switch <slug> or "switch to X".
disable-model-invocation: true
---

Switch to: $ARGUMENTS

The vault root is the path on the session-start `Vault:` line; without that line, the `default` vault in `~/.config/adhd-planner/vaults.json` (or `$ADHD_PLANNER_VAULTS`) when that file loads; otherwise the plugin's vault path option `${user_config.vaultPath}` (skip it when empty), else `$VAULT`, else `~/vault`, the session-start hook's order. Every `~/vault` path below means that root. When `vaults.json` registers several vaults (the `Vault name:` line lists the others), `<vault>:<slug>` names a task in another vault, and `<vault>` is the vault's name in `vaults.json`, and its root is that entry's `path`.

1. No argument → list notes with `status: active` or `parked` in every vault's `Tasks/` (the current one, plus each vault in `vaults.json` whose path has `Tasks/`), max 5 overall, most recent first, each as `<vault>:<slug>` (plain `<slug>` when only one vault is registered), and ask which.
2. Run `/tasks:task-park` on the current active task.
3. Resolve the target: exact slug, else match `aliases`. Not found → offer `/tasks:task-start`. A `<vault>:` prefix looks only in that vault; without one, look in the current vault first, then the others (several matches → list them and ask).
4. Set target `status: active`; write its slug to `<target vault>/Tasks/.active` and to `<target vault>/Tasks/.session/$CLAUDE_CODE_SESSION_ID` (create `.session/`). If the target is in another vault than the current one, delete `<current vault>/Tasks/.session/$CLAUDE_CODE_SESSION_ID`, so the older override cannot win. If `CLAUDE_CODE_SESSION_ID` is empty, write only `.active` and say the choice applies to every session.
   If the target's `repo:` is empty and the current directory is in a git repo, set `repo:` to `git rev-parse --show-toplevel`, written with `~` for `$HOME`: with the old task parked, the active target wins this repo after `/clear`. If `repo:` already names another folder, leave it.
5. Reply: `Switched to <slug>. Run /clear to load it fresh.` The exception: when the vault changed and step 4 did not bind this repo to the target and the current folder is not under one of the target vault's `folders` in `vaults.json`, `/clear` starts a new session id, the `.session/` override no longer applies, and this folder resolves the way the session-start hook does: a non-`done` note in any vault whose `repo:` holds this folder (deepest wins), else the vault whose `folders` holds it (deepest wins; its `.active`), else the default vault's `.active`. Work out which of those this folder gets; call it `<vault'>:<slug'>`. Then do not suggest `/clear`. In the reply, `vaults.json` means the file this session uses, named by its full path: `$ADHD_PLANNER_VAULTS` when set, else `~/.config/adhd-planner/vaults.json`. Reply `Switched to <vault>:<slug>. Stay in this session: after /clear this folder shows <vault'>:<slug'> again.` and add how to make it stick: if this folder (or a parent) is in another vault's `folders`, `move that entry from <that vault>'s "folders" to <target vault>'s in vaults.json` (never list one folder under two vaults: vaults.json then fails to load and every session falls back to the single default vault); otherwise `add this folder to <target vault>'s "folders" in vaults.json`; in a git repo, also `or set the target's repo:`. Add `Bound to <repo>.` when step 4 set `repo:`. When `repo:` names another folder and this repo has its own task, add: `After /clear this repo shows <that task>; /tasks:task-switch again or stay in this session.` When the vault changed, add `Vault now: <name> (<path>).` and use that path as the vault root for the rest of this session.
