name: task-start
description: Start working on a task now, new or existing: create its note when there is none, then make it this session's current task. Use when the user runs /tasks:task-start <slug> or "start a task for X", "start X". Not a backlog or batch of tasks to do later (create-task); picking an existing task from a list: task-switch.
disable-model-invocation: true

Start task: $ARGUMENTS

The vault root is the path on the session-start `Vault:` line; without that line, the `default` vault in `~/.config/adhd-planner/vaults.json` (or `$ADHD_PLANNER_VAULTS`) when that file loads; otherwise the plugin's vault path option `${user_config.vaultPath}` (skip it when empty), else `$VAULT`, else `~/vault`, the session-start hook's order. Every `~/vault` path below means that root. When `vaults.json` registers several vaults (the `Vault name:` line lists the others), `<vault>:<slug>` names a task in another vault, and `<vault>` is the vault's name in `vaults.json`, and its root is that entry's `path`.

1. An argument `<vault>:<slug>` targets that vault: strip the prefix before making the slug, and in steps 1–4 and 6–7 read `~/vault` as that vault's `path` from `vaults.json` (step 5 handles the current vault's task, so it stays on the current vault); otherwise use the current vault. When it is not the current vault, also delete `<current vault>/Tasks/.session/$CLAUDE_CODE_SESSION_ID` in step 6 (as task-switch does), and add `Vault now: <name> (<path>)` to the reply. Slug = kebab-case of the argument. Find the note: `~/vault/Tasks/<slug>.md`, else a note whose `aliases` match (several matches → list them and ask).
   - Note found with `status: done` → say it is finished and stop.
   - Note found otherwise (backlog or parked) → it is an **existing** task: skip steps 2–4.
   - No note → it is a **new** task: steps 2–4 create it.
2. New task: ask the user in ONE message: goal (one line), project/area it belongs to, first action. Skip what the argument already answers.
3. New task: confirm the project/area hub exists in `Projects/` or `Areas/` (obsidian-vault rule 3). Missing → ask before creating it.
4. New task: copy `~/vault/Templates/Task.md` to `~/vault/Tasks/<slug>.md`; set `priority` to the one the user named, else `p3` (do not ask); set `due` (`YYYY-MM-DD`) only when the user gives a date, otherwise leave `due:` empty (accept only `p0`..`p5` and a real `YYYY-MM-DD` date; for any other value ask the user to correct it before writing the note); fill `up`, `started` (today: the date on the latest `Now:` line), `aliases`, Goal, Next (as `- [ ]` with a time estimate). Leave `repo:` empty here; step 6 sets it.
5. **Ask before replacing the current task.** The current task is, first match: the task this session last started or switched to; else the session-start `Current task:` line; else `~/vault/Tasks/.active`. None → skip this step (`keep` below is false). It is the target → reply `Already on <slug>.` and stop, writing nothing. It is **this session's** task when `~/vault/Tasks/.session/$CLAUDE_CODE_SESSION_ID` names it (the `Current task:` line then says `(this session)`) or this session started or switched to it; otherwise it is **global** (picked by `repo:`, a vault's `folders`, or `.active`), and another session may be on it. Ask in ONE message, before writing anything in steps 6–7 (a new note from step 4 is fine):
   - This session's task: `Park <current> and start <slug>?` Yes → run `/tasks:task-park` on it. No → stop.
   - Global task: `<current> is the current task outside this session. Park it, or leave it as is and only assign <slug> to this session?` Park → run `/tasks:task-park` on it. Leave → touch nothing of it and set `keep`.
   With `CLAUDE_CODE_SESSION_ID` empty there is no session to assign to: offer only the park question.
6. Set the target `status: active`. Write its slug to `~/vault/Tasks/.session/$CLAUDE_CODE_SESSION_ID` (create `.session/`), and to `~/vault/Tasks/.active` unless `keep` (the global task keeps `.active`). If `CLAUDE_CODE_SESSION_ID` is empty, write only `.active` and say the choice applies to every session.
   Unless `keep`: if the target's `repo:` is empty and the current directory is in a git repo, set `repo:` to `git rev-parse --show-toplevel`, written with `~` for `$HOME`. If `repo:` already names another folder, leave it. With `keep`, leave `repo:` as it is: binding it would make the target outrank the global task for every other session in this repo. A `repo:` the target already has is the user's and stays; when it holds this folder, the target outranks the global task there anyway, so step 8 says so.
7. Append to today's daily note `## Log` (create from `Templates/Daily.md` if missing): `- [[<slug>]] started` for a new task, `- [[<slug>]] resumed` for an existing one.
8. Verify per obsidian-vault (unresolved, backlinks on the hub). Reply: the first Next action, nothing else; after a `keep`, add `Left <current> as is. Stay in this session: after /clear this folder shows <current> again.` When the target's `repo:` holds this folder, say instead: `<slug> is bound to <repo>, so other sessions in this repo show it too, not <current>.` With several vaults registered, start it with `<vault>:`; on a cross-vault start, put step 1's `Vault now: <name> (<path>)` line before it.
